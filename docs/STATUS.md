菜单生成当前产品范围为满12个月且月龄、过敏状态已确认的宝宝。过敏校验仅匹配明确名称，不覆盖全部别名和复合配料，不是安全或营养认证。一次拒吃不应被推断为永久不喜欢；异常反应记录不等于确诊过敏。

## 最新需求与下一步

核心流程：历史回看与实际反馈 → 结合现有食材推荐 → 核对菜单 → 按缺口买菜 → 实际进食记录。已安排不等于已做或已吃，未记录不等于没吃；仅知道食材名称不代表余量够用。不建立复杂采购流水账或强制克重记录。

[CORE_SCENARIOS.md](CORE_SCENARIOS.md)记录详细场景和新增记录建议；建议项与已确认项分别标注。[ROADMAP.md](ROADMAP.md)拆分任务及验收条件。

**本轮已实现**：R1日/周对照回看与轻量补记。直接复用实际记录接口；参考菜单填写默认接受情况为“未说明”，经明确核对再保存，不把菜单配料自动变成吃过的食物。尚无菜单与记录的持久外键关联，也未新增数据库迁移。

**下一项可立即开展**：R2共享食材及虚构验收数据；之后R3推荐上下文、R4采购缺口均无需先部署ECS。

**暂停**：ECS手动安装和部署继续暂停，等待外部自动执行链路。自动触发、连接及部署回执尚未接入此仓库，不能宣称Codex已经连通用户ECS。语音和小程序在文本核心流程之后实施。
