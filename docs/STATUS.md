## 已实现

| 模块 | 当前能力与界限 |
| --- | --- |
| 家庭身份 | 全家统一网址、一次性邀请、30天会话、原成员重新登录、成员停用；不是微信官方OAuth |
| 档案与进食 | 已确认月龄/过敏、做饭时间、喜好和备注；共享实际记录、补记、更正、撤销与审计；自然语言先生成私人草稿 |
| 回看 | 日/周对照菜单与实际记录，显示来源、份量、接受情况及暂无记录；参考菜单填写必须核对。菜单是当前保存版本，非完整版本时间线 |
| 家里食材 | 名称、数字或粗略余量、位置、生熟类型、用完状态、最后确认；全家共享、批量原子写入、修订冲突、重试去重、修改追溯 |
| 食材自然语言 | 从原话整理私人草稿；不明食材、计划或位置含糊时追问；可更正，明确确认后共享。无法核实的口语数字保留原话为粗略说明，不猜换算 |
| 菜单推荐 | 结合档案、近七天菜单/实际记录及近期确认原料；草稿展示有界资料快照、覆盖范围和引用；核对后发布及单餐替换 |
| 旧草稿保护 | 档案、目标菜单或库存修订有变化，菜单不能沿用旧草稿发布；参考库存随时间变为待确认也会阻止发布 |
| 采购缺口 | 按已发布菜单聚合后，抵扣一次同名同单位原料；分为需买、已登记足够、待核对。数量不明、单位不同、库存陈旧不静默抵扣；熟食不当原料 |
| 买菜后反馈 | 可从采购页进入食材清单，确认家中实际总量后返回并重算。发布菜单、记录进食和读取采购都不自动扣库存 |
| 只读问答 | 可参考近七天家庭资料、现有原料及当前/未来菜单；不直接写业务事实 |
| 运维准备 | SQLite迁移、一致性备份、导出含食材、配置工具、Compose与GitHub Verify；新增003迁移，测试旧版升级与备份恢复 |
| 语音 | 仅本地录音回放，不识别、不上传、不产生语音回答 |

## 边界与下一步

- ECS手动安装和部署继续暂停，等待外部自动执行链路；不能宣称已连通或自动部署。用户ECS已安装Docker/Compose，开发环境状态不能代替ECS状态。
- 下一阶段为真实模型与浏览器/微信验收，以及接入链路就绪后的隔离部署；密钥只通过安全配置注入，不在聊天或公开Git中发送。
- 采购匹配采用规范化的明确名称与相同单位，不猜食材同义词、不换算斤/克等，份的规格需核对；清单可通过更正库存或菜单后重算，尚无独立共享采购覆盖单。
- 默认7天未核对的库存需要重确认，可配置1–30天；这是资料新旧策略，不代表任何保质期或食物安全承诺。
- 生熟与可食用状态由家人核对。已安排不等于已做或已吃，未记录不等于没吃。进食和库存混合在同一句时尚无一键双类写入，请分开入口处理。
- 菜单生成产品范围满12个月；明确过敏名称匹配不覆盖所有别名和复合配料，草稿不是医学/营养/安全认证。
- 人数、设备和做法偏好等独立字段仍是可选设计建议，可先记备注，不要求每天填写全量健康日记。
- 定时异机加密备份、数据删除界面、金额预算、完整语音与小程序仍需后续工作；供应商次数上限不等于金额硬封顶。
