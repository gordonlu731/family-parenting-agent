# ECS自动执行链路的接入准备

当前约定：ECS手动安装和部署暂停，等待外部自动执行链路打通。本仓库的Verify仅构建及测试，不连接ECS、不调用真实模型、不部署。用户无需先配置ECS密钥来运行这些检查。

## 可复用验证入口

安装Python 3.12依赖及Node 24依赖后，执行bash scripts/verify.sh。该命令先构建dist，再跑后台测试，任一失败返回非零。GitHub工作流使用此入口，第三方Actions固定到已核实的提交。测试不依赖真实密钥。

## 外部执行器需要提供

- 只针对本项目操作，隔离目录、Compose项目名family-parenting-agent、数据库卷和主机回环端口18080；执行前只读检查现有服务和占用情况。
- 发布使用完整已审核commit SHA，不仅使用可变main分支；返回仓库、commit、任务编号、步骤状态、退出码及脱敏错误摘要。
- 对同一发布请求去重，单项目互斥，超时可诊断；不能因丢失回执就重复执行数据库或发布操作。
- 生产凭证在服务端保管，不写公共仓库、任务参数、日志或CI输出；日志不含家庭导出、录音或数据库正文。
- 开始部署前完成一致性备份和恢复演练，保留原配置及卷。停止/回滚仅操作此项目；禁止删除数据卷或变动量化服务。
- 健康检查用/api/health；真实模型另做合成样例检查；家庭登录、共享及微信测试另行验收。HTTP健康不代表业务全部通过。

本文件是接入契约，不表示执行器已支持这些能力，也未为育儿仓库配置触发ECS的工作流。链路就绪后先验证只读检查和回执，再接入实际部署。
