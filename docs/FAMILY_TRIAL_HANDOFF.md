# 正式家庭试用交接（尚未开放）

当前私人回环服务中的家庭为虚构验收空间，不直接录入真实宝宝资料。

## 最少外部准备

- 在本项目当前发布目录的600权限.env中安全配置MODEL_API_KEY，确认BASE_URL/ID与账号地域匹配。不要在聊天/Git粘贴密钥。真实请求全轮最多8次（含失败/重试），本轮缺Key，调用0次。
- 提供确定的家庭域名、DNS管理条件，并确认管理员配置HTTPS代理与80/443入站的权限。当前未发现443监听或活动Caddy/nginx/apache。18080始终不开放公网。
- 异机备份还缺专属私有存储、安全身份、加密接收方及恢复私钥保管办法。现有14份本机明文副本不算灾备。

## 私人访问与HTTPS准备

使用现有专属SSH配置及主机pin，经既有路由添加 `-L 18080:127.0.0.1:18080`，访问http://127.0.0.1:18080。
不更换身份，不关闭主机验证，本机转发不要绑定0.0.0.0。这不是正式微信入口。

管理员审阅Caddyfile.example，将域名替换为确认域名，代理仍指向127.0.0.1:18080；安装前备份原代理配置，保留其他站点。
需核实DNS、证书签发与80/443入站，不能直接覆盖现有代理配置。本轮未执行系统操作。
2026-11-15源码已补user_service的HTTPS origin支持：必须是无用户信息/查询/片段/业务路径的完整HTTPS origin，并强制COOKIE_SECURE=true；应用仍回环监听。该补丁尚未部署到ECS，不能直接在旧发布上改.env。先通过新提交验证并准备匹配的发布/备份监测路径，待代理和证书实际可用后再切换；保留旧配置和回退版本。不以Cookie校验通过代替TLS证书或微信验收。
域名确定后再做证书、HTTP跳转、Secure/HttpOnly Cookie、Origin/CSRF、匿名拒绝及浏览器登录刷新验收。
