# 换餐与两人流程：离线诊断

2026年11月16日。应用仍0.3.5；本轮只修改评测工具，不迁移数据、不重启应用、不重置8/8请求账本。工具已在开发环境验证，尚未在用户ECS读取原失败现场。Key已配置，不再索要。

## 解决什么问题

旧评测仅返回machine_acceptance_assertion_failed，缺少具体断言和步骤。现在报告包含failure_step、仅源码相对位置的failure_location、具名steps及HTTP预期/实际状态；stdout只显示案例/步骤/原因和计数，不输出回复正文、令牌或私密文件路径。

p10统一流程现在验证两位照顾者共享菜单/库存、照护者更新买后总量、实际记录归属、回看、私人换餐草稿、核对后仅改目标餐、保留晚餐/实际/库存和采购只读。合成运行共31项步骤检查。注入“误改晚餐”等故障会在对应步骤明确失败，不放宽旧业务约束。

**原始失败的回复没有保存，工具不能凭空恢复。** 新的合成流程/离线回放通过，只证明相应夹具与业务规则；不等于2026年11月15日失败的真实换餐已复现、修复或通过。

## 不收费的自检与回放

在源码目录使用项目venv执行；输出文件必须是新路径，以下示例首次使用后需换新文件名。工具拒绝覆盖报告。无需加载现有家庭库或Key。

```bash
python scripts/evaluate.py --cases p10 --mock-model --capture-responses --output data/evaluations/p10-source.json
python scripts/evaluate.py --cases p10 --replay data/evaluations/p10-source.json --output data/evaluations/p10-replay.json
```

第一条明确使用合成回复，不访问供应商；第二条为offline_replay，不构造真实HTTP客户端。两者均使用临时虚构库，不打开配置的生产APP_DB。源报告要求当前用户所有、权限600、不含符号链接、不超过4MiB；报告在仓库中只能写入忽略的data/，也可写仓库外私密目录。不要提交这些报告。

源报告必须含provider_replies数组；仅有outputs、摘要或“HTTP200”的旧报告会被拒绝，不从缺失回复中编造重现。回复缺失、操作类型不符、日期不符或未用完都明确失败，绝不回退到真实模型。

跨日期回放必须显式加--rebase-replay-dates：只按已捕获的请求基准日期平移结构化菜单/记录日期，不改源文件，报告replay_date_rebasing=true。这是经过变换的回放，不是原始现场；没有日期锚点时拒绝。菜名、实际进食原话等自由文本不会自动改写。

## 私密回复留存的边界

--capture-responses只在显式mock/replay或既有已授权的live模式使用。它不授权新的真实请求，本项目当前真实验证额度已经耗尽。

开启时，回复返回后、业务断言前就写入并fsync私密报告，保留案例、操作类型、请求日期、来源模式、状态、completion的content/finish_reason及非负整数usage。丢弃请求提示、鉴权/响应头、供应商HTTP错误正文，不回显异常消息；故障注入仍独立标记，不伪装成真实回复。生成内容仍可能敏感，报告必须保持私密。

mode=mock_model、offline_replay、live_model分别记录；quality_certified始终false，人审保持pending。回放不会修改原有真实验证定义的not_run状态，也不会重置服务器账本。
