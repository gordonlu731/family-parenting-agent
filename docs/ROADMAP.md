## 开发推进方式

- 每次集中完成一个能独立检查的功能：核对场景与数据 → 实现界面和接口 → 相关自动验证 → 更新文档 → 提交GitHub。遇到问题先修复，不带着失败进入下一阶段。
- R1先复用已有数据，R2才新增食材迁移；R3/R4复用统一的食材事实与菜单配料，避免各自建立不一致的库存。
- Codex负责设计、实现、模拟测试、文档和提交。真实模型、费用与终端体验单独验收；需要账号或家人手机时再让用户参与，不反复要求手动ECS命令。
- 所有功能在临时数据库和虚构数据上先验证。实际部署已获授权；完成代码不代表家人已经能访问。
- 本轮R1–R4已实现并通过后台模拟验证（83项测试），代码侧基础流程已串联；下一阶段E1–E3及R5真实模型/微信验收，之后再推进语音。本地浏览器环境受限，已用独立CI完成桌面/手机尺寸回归；微信真机不能由CI替代。
