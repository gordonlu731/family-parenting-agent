# 下一阶段 Codex 开发交接

用户已确定：个人家庭使用，家人主要用微信，先手机网页H5，后续加入一句一答和连续语音。ECS已升级到至少4GB，无域名；不因缺域名停止开发。维护者已选择公开源码，仓库为https://github.com/gordonlu731/family-parenting-agent，与量化项目隔离；家庭数据和凭证保持私密。当前0.2.1未部署。

## 当前实现

普通 `/api/assistant` 为只读问答。`/api/record-proposals` 生成进食草稿，`/api/menu-proposals` 生成菜单草稿；`PUT /api/proposals/{id}` 更正，`POST /api/proposals/{id}/confirm` 在明确核对后写入。草稿私有、24小时有效，发布后记录和菜单共享。菜单生成产品范围为12个月及以上。

记录抽取检查食物、份量及证据是否来自原话，但语义理解仍需人核实。计划词先触发澄清。多餐发布先检查全部版本，再在同一事务提交；不能覆盖生成后他人改动。采购估算只从已发布菜单读取。

`ai_usage` 预留调用名额后才访问供应商。默认每天全家30次尝试、包含失败；请求成功后同编号复用结果，不能把次数上限当作金额预算。JSON模式及Schema校验失败不写业务事实。

## 下一步优先级

1. 先取ECS只读环境检测结果，再按FIRST_RUN.md配置。默认qwen-plus及百炼北京地域兼容地址；API Key须对应地址地域。`MODEL_ENABLE_THINKING=false`已支持。密钥通过隐藏输入的configure或服务器密钥管理注入，不在普通聊天发送。使用其他模型时核实参数，不把Qwen专用字段无条件发送给其他厂商。
2. 用约20条真实家庭说法评测：实际与计划混合、拒吃、含糊份量、昨天/今天、未说餐次、方言转写、过敏配料、缺字段、超时、截断、重复提交。记录真实结果，不把模拟HTTP测试当准确率证据。
3. 完成页面视觉和交互检查：375px、430px及桌面。旧预览因环境错误停止；仅在有恢复证据或符合预览服务文档的具体修复时重试，不通过网络或其他浏览器控制方式绕过。
4. 评估ECS现有服务与端口后隔离部署；当前没有服务器访问。稳定对家人开放前核实域名、HTTPS及发布条件，做两位家人的独立手机会话测试。
5. 增加AI局部换菜、对话发起任务、可追溯食材别名和复合配料校验、数据删除及费用管理。保持权限和食材约束由后台执行，不能只靠提示词。

## 语音阶段

VoiceTest仅为30秒以内本地录音回放，不上传、不转写、不聊天。先在家人实际微信中验证HTTPS授权、格式、播放、来电和后台切换。

随后接ASR→现有业务服务→TTS，或评测实时语音。复用家庭权限、请求编号及草稿确认，设置时长上限和结束按钮。打断播报不自动撤销已经保存的记录。长期密钥不放浏览器，音频默认不长期保存。

小程序客户端另立阶段，先核实个人主体和AI问答类目，不承诺个人身份一定可正式发布。

## 上线准备

先备份并验证迁移、恢复和回滚；补齐异机加密备份、保留及删除策略、管理员恢复、金额预算、运行监测。完成真实模型及微信验收后，再发给家人正式使用。

固定项目名使用 `docker compose -p family-parenting-agent`；如旧部署用自定义项目名，继续沿用原名和卷，不擅自切换。默认APP_PORT改为18080，升级时同步核对主机代理；不使用down -v处理升级问题。当前工作环境没有Docker，不代表用户ECS未安装。
