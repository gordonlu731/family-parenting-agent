# 小芽家庭育儿助手

手机网页开发试用版 0.3.0。供一个家庭通过独立身份，共同维护宝宝档案、菜单和实际进食记录。正式目标是微信中打开链接使用；此包尚未部署上线，也未完成微信真机验收。

最近需求：回看历史计划和实际进食，维护全家共享食材，结合反馈推荐菜单，再按家中余量生成采购缺口。历史回看、共享食材、带家庭资料的推荐及采购缺口计算均已有首版实现；真实模型效果与微信体验待验收。 ECS手动部署暂停，等待外部自动执行链路；本地开发与模拟验证可继续。

## 已实现

- React/TypeScript 手机和桌面页面，包含今日、进食记录、问助手、我的家庭。
- FastAPI 后台与 SQLite 持久化。浏览器只保存登录 Cookie，宝宝共享数据在服务器数据库。
- 一次性家庭初始化、单次有效邀请、30天会话、成员停用和管理员恢复登录工具。
- 家庭档案、手工菜单、实际进食记录的添加、更正和撤销。
- “回看”按一天或七天对照当前保存的菜单与实际记录，显示记录人、份量、接受情况及暂无记录的餐次；可直接补记和更正。参考菜单填写须核对实际情况后保存，未记录不等于没吃。
- 幂等操作、相同餐次重复记录提醒、版本冲突检查、修改历史。
- 管理员数据导出、SQLite 一致性备份工具。
- 页面内麦克风录音与回放兼容性测试，录音不上传服务器。
- 可配置的文本问答；普通问答只读，不把聊天自动保存成实际进食。
- 一句话整理进食记录：检查结构、原话中的食物和份量，生成私人草稿，核对或修改后再保存到家庭记录。
- 根据已确认档案和近期记录，生成1、3或7天菜单草稿。管理员逐餐核对和编辑后统一发布；发布时再次检查档案版本、菜单冲突和明确过敏食材。
- 全家共享“家里食材”：名称、粗略或数字余量、位置、生熟类型、用完状态和核对时间；表单明确确认后保存。
- 一句话整理食材为私人草稿，更正、核对后再更新共享清单；多人修改有版本检查，重试不重复写入。
- 菜单生成与只读问答使用近期历史菜单、实际反馈及已确认原料；菜单草稿展示资料覆盖范围和推荐依据。食材变化或需要重确认后，旧菜单草稿不能直接发布。
- 采购清单先合并所有已发布菜单需求，再抵扣一次同名同单位的已确认原料，区分需买、足够和待核对。余量不明、不同单位及熟食不被静默当作足够；读取清单、发布菜单或进食记录不扣库存。
- 全家共享的每日AI调用次数上限、供应商返回的token记录和请求去重。默认每天30次，包含失败尝试；不是人民币账单封顶。
- 默认无模型密钥，不调用模型、不生成模拟AI回复。上述AI流程用模拟HTTP验证，尚未连接真实模型。

## 尚未完成

独立采购清单手工覆盖、可靠食材同义词归一、真实模型场景评测、对话中直接发起任务、可靠的复合配料过敏识别、原始数据删除管理界面、按金额的生产费用控制、定时异机加密备份、完整语音对话与小程序客户端。

当前AI菜单生成功能的产品范围为已满12个月、月龄和过敏状态经家长确认的宝宝；不覆盖未满12个月的喂养安排。草稿有效期24小时，仅创建人可见，确认后的记录和菜单供家庭共享。

当前菜单校验仅匹配家长配置的明确食材名称，不能覆盖所有别名及复合配料，不能作为食物安全认证。页面已提示家长核实；档案变化会给已有菜单添加复核提示。演示档案、初始记录和菜单均为虚构。

代码入库和云端开发环境说明见 [仓库与云端开发](docs/REPOSITORY.md)，开发约定见AGENTS.md。

## 本地开发

要求 Python 3.12、Node.js 22.12及以上或Node.js24。开发环境未设置模型密钥时不产生模型调用。

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
npm ci --ignore-scripts
npm run dev
```

打开开发服务器输出的3000端口地址。点击“体验一个演示家庭”创建独立演示空间。开发模式使用 `data/demo.sqlite3`，不应暴露到公网或录入真实儿童隐私资料。开发模式允许HTTP Cookie，仅为本机测试；实际微信录音需要HTTPS环境验证。

邀请链接中的令牌放在URL片段，避免出现在普通HTTP请求日志中。每个邀请单次有效、24小时过期。新设备重新加入需要管理员新发邀请，不能只凭昵称获取身份。管理员若需要退出，先保存自己的重新登录链接。

## 服务器试用准备

先按 [首次试运行指南](docs/FIRST_RUN.md) 操作。`python3 scripts/deploy.py check` 仅检查Docker、磁盘、端口及配置，不调用模型或安装软件。`configure` 交互式生成权限600的.env，隐藏输入API Key，拒绝覆盖已有配置。默认qwen-plus，使用百炼北京地域兼容地址；该模型服务地域不由ECS地域决定，API Key须与服务地址对应。

`python scripts/check_model.py --call-model` 是显式付费连通测试，只发送固定测试句，不读取家庭数据库。该操作须在配置好模型环境的容器内执行，不会因运行check而自动触发。

## 生产部署准备

先核实ECS资源、现有服务、域名及发布条件，和量化项目隔离。此项目不包含自动创建付费云资源、公开仓库或修改现有服务的操作。

1. 安全配置 `.env`，以 `.env.example` 为字段说明。设置随机且至少32字符的 `BOOTSTRAP_TOKEN`、真实 `PUBLIC_ORIGIN`，保留 `DEMO_MODE=false` 与 `COOKIE_SECURE=true`。
2. 用 `docker compose -p family-parenting-agent up -d --build` 构建运行。应用默认只绑定主机回环18080端口（APP_PORT可配置），数据库使用独立持久化卷。先确认该端口未被其他项目占用。
3. 在主机上的HTTPS反向代理中配置域名，参考 `Caddyfile.example`。该示例假定Caddy运行在主机，不能直接复制成其他容器内的回环代理。
4. 在私有家庭入口使用初始化凭证创建家庭；完成后该初始化接口拒绝再次建家。凭证不要写进代码或公开日志。
5. 如需接入AI，设置普通业务API的 `MODEL_API_KEY`、`MODEL_BASE_URL`、`MODEL_ID`。后台使用OpenAI兼容Chat接口，API base URL不含末尾 `/chat/completions`。记录整理和菜单生成还要求模型支持 `response_format: {"type":"json_object"}`。部分模型需关闭思考模式，应以所选服务的官方文档为准；`MODEL_ENABLE_THINKING=false` 可显式关闭支持此参数的模型的思考模式；其他厂商可留空，不发送该字段。实际账号、地域、模型能力及计费在接入时核实。设置 `MODEL_DAILY_REQUEST_LIMIT` 控制全家每天的调用尝试数，同时在供应商控制台设置适用的余额或消费告警。
6. 完成至少两部手机的家庭共享测试，再用实际微信录音与播放测试；必要时调整Cookie、域名和音频接入方案。

以上是运维交接，不代表Docker镜像已经构建、证书已经签发、域名已经可访问或模型已经验证。编译包保留完整源码，可由后续Codex开发环境直接接手。

## 家人登录

全家使用同一网址，在“我的家庭”中可复制统一入口并在微信收藏。首次通过管理员私发的一次性邀请加入，登录状态保留30天；浏览器缓存被清理、主动退出或更换浏览器/设备后可能需要重新登录。

已有成员由管理员在成员列表点击“重新登录”，私发生成的链接。链接打开后显示家庭及原成员称呼，点击确认登录，无需重复输入昵称；沿用原成员身份及历史记录，不新增成员。邀请预览不会消耗链接，确认后才使用。链接24小时有效、单次使用；停用成员后恢复链接失效。

这不是微信官方OAuth登录。微信只负责打开链接，应用凭登录会话识别成员。正式登录保持与复制体验仍需在实际微信设备验证。

## AI操作与升级

“今日”或“进食记录”中的“说一句，整理记录”先显示可编辑草稿，必须勾选实际情况确认，再保存。信息不足时需补充原话后重新整理。此版本不会从普通问答自动发起写入任务。

管理员在“生成菜单草稿”中选择1、3或7天并填写要求，核对每餐菜名、配料、处理方式及采购量后发布。多餐发布在一个数据库事务中完成：有任一菜单冲突则全部停止。单餐可手工修改，也可在已有菜单中选择“让助手换一道菜”，填写替换要求并生成单餐草稿，核对后只更新该餐及采购估算。原餐被修改或档案变化时旧草稿不能发布。

首次启动按编号应用增量迁移；0.3.0新增 `backend/migrations/003_pantry.sql`，创建共享食材与修订号，并为私人草稿增加资料快照，保留原有家庭资料和记录。升级前先备份并验证恢复；若回滚到0.1.0，应使用升级前备份并保留升级后的数据副本，不在运行中覆盖数据库。

食材、推荐资料与采购规则见 [DATA_RULES.md](docs/DATA_RULES.md)。`PANTRY_RECONFIRM_DAYS`默认7天，仅控制资料重确认提示，不是保质期。库存不自动精确扣减，买完后填写家中实际总量。

无域名不影响继续开发和隔离测试。对家人开放的稳定入口、HTTPS及中国大陆部署相关手续，在正式发布时单独核实与配置。

## 备份与恢复

应用容器内运行一致性备份，目标必须是不存在的新文件：

```bash
docker compose -p family-parenting-agent exec app python scripts/manage.py backup /data/backup-20261106.sqlite3
```

应由部署人员安排把备份复制到独立存储并加密，配置保留周期和自动任务。当前版本不自动上传、不自动定期备份。

恢复时先停止应用，备份原有持久化目录，将经过 `PRAGMA integrity_check` 验证的备份安装为应用数据库文件，清理对应旧WAL/SHM前确认没有进程持有数据库，确认文件权限，再启动应用。不要在运行中覆盖数据库文件。先在隔离目录完成一次恢复演练，再处理真实数据。

管理员丢失会话后，可由有服务器权限的运维人员执行：

```bash
docker compose -p family-parenting-agent exec app python scripts/manage.py invite-owner
```

输出是24小时内单次有效的秘密登录路径，只私下交给管理员。开发测试和服务日志不应打印它。
